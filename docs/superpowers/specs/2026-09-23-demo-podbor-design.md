# Демо-версия программы подбора: ВЦ 4-70 (2,5 / 3,15 / 4)

**Источник:** `PRD.md` («Решение», следующий этап). Цель этого спека — не вся программа из PRD,
а суженный прототип для проверки на первых пользователях (проектировщики, монтажники,
снабженцы).

## Цель и аудитория

Прототип, который Андрей показывает узкому кругу реальных проектировщиков/подрядчиков (не
публичный виджет на лендинге, не инвесторская демка). Задача — проверить, пользуются ли им и
что говорят, а не собрать заявки массово.

## Что демо делает

Пользователь вводит рабочую точку и параметры → демо проверяет её по оцифрованным кривым Q-P
трёх типоразмеров ВЦ 4-70 (2,5 / 3,15 / 4) Теплomash → возвращает список подходящих
комплектаций (типоразмер × диаметр колеса × обороты × двигатель), отсортированный по КПД, с
точкой на графике и чертежом выбранной модели.

## Явные границы (что НЕ делает демо)

- Не ищет аналог оборудования **другого завода** — это следующий этап PRD. Демо подбирает
  только внутри линейки ВЦ 4-70 (3 типоразмера).
- Не использует частотный преобразователь (ЧП) — обороты фиксированные, как в таблице
  каталога. Диапазон регулирования через ЧП — за рамками демо.
- Исполнение (материал/защита: общепромышленное, коррозионностойкое и т.д.) влияет только на
  подпись/маркировку в результате и на то, какой вариант чертежа показывается — не на
  аэродинамику (кривая одна и та же для всех исполнений одного типоразмера/диаметра).
- Не работает с 0,95D / 1,05D как «неважными» — все 5 диаметров каждого типоразмера входят в
  объём (см. ниже), но это единственное расширение против совсем минимального демо; углы
  поворота корпуса, доп. оборудование (виброизоляторы, вставки, сетки) и вариант с входным
  ниппелем — вне объёма.

## Источники данных

Три PDF каталога Теплomash (переданы Андреем):

- `ВЦ 4-70-2,5.pdf`
- `ВЦ 4-70-3,15.pdf`
- `ВЦ 4-70-4.pdf`

Каждый содержит: график D=Dном (стр. 1), таблицу технических характеристик по всем парам
диаметр×обороты (стр. 2), чертёж с габаритными размерами и таблицей по углу поворота корпуса
(стр. 2), и 4 дополнительных графика — 0,9D / 0,95D / 1,05D / 1,1D (стр. 3).

## Объём оцифровки

Все 5 диаметров на каждый из 3 типоразмеров (как у партнёра — это единственный способ
воспроизводить подборы вроде примера из образца принтаута, где выбранная модель была не
номинального диаметра). Итого ориентировочно:

- ВЦ 4-70-2,5: 5 графиков × 2 кривые оборотов ≈ 10 кривых n=const
- ВЦ 4-70-3,15: 5 графиков × 2 кривые оборотов ≈ 10 кривых n=const
- ВЦ 4-70-4: 5 графиков × 2-3 кривые оборотов ≈ 12 кривых n=const

Итого **≈ 30 кривых n=const**, плюс кривые КПД (нужны для сортировки результатов) и кривые
постоянной мощности Ny=const (нужны для поля «мощность на валу» в результате) на тех же
графиках. Вспомогательная ось `Pdv, Па` есть под каждым графиком — используется для коррекции
статика→полное давление (см. ниже), отдельно калибруется по разделу 0 методички
[[podbor-ventilyatorov]].

## Подготовка данных (офлайн, один раз)

По методике [[podbor-ventilyatorov]], раздел «Оцифровка графика» — «Трассировка кривых»:

1. Рендер страниц PDF в PNG высокого разрешения.
2. Калибровка осей (лог-лог) локально для каждого графика — Q и Pv, отдельно Pdv (`Pdv=C·Q²`).
3. Трассировка каждой кривой n=const → 5-10 точек → квадратичная аппроксимация
   `P = a·Q² + b·Q + c`.
4. То же для кривых КПД (η) и постоянной мощности (Ny) — где они читаемы на графике.
5. Контроль: сверить 2-3 точки полученных кривых с диапазонами из таблицы технических
   характеристик (столбцы «Производительность» и «Полное давление» по каждой строке
   диаметр×обороты) — расхождение фиксируется, а не замалчивается.
6. Результат сохраняется как один JS-модуль с данными: массив кривых, каждая —
   `{typorazmer, diameter, rpm, coeffs: {a,b,c}, qRange: [min,max], eta?: {...}, power?: {...}}`
   + калибровочные константы (для точки на картинке) + пути к файлам изображений графиков и
   чертежей.

## Экран демо

Отдельная статическая страница `podbor.html` в этом же репозитории (без сборки, без внешних
ресурсов — тот же принцип, что и у `index.html`), со ссылкой с лендинга.

### Форма ввода

- Расход требуемый, м³/ч *
- Давление требуемое, Па *
- Тип расчёта: Статический / Полный (по умолчанию — Полный; выбор статического запускает
  коррекцию через ось Pdv на этом Q)
- Допустимое отклонение вверх / вниз, % (по умолчанию 30 / 15, как у партнёра — можно менять,
  от значения зависит, сколько вариантов найдётся)
- Температура воздуха, °C (влияет на плотность воздуха и, соответственно, на пересчёт давления;
  по умолчанию 20)
- Исполнение (общепромышленное / коррозионностойкое / и т.д. — список из «Варианты
  изготовления» каталога) — влияет только на подпись в результате и вариант чертежа

### Расчёт (чистый JS, без бэкенда)

1. Если тип расчёта — «статический»: считать `Pdv` на заданном Q по оцифрованной оси Pdv,
   прибавить к заданному P → получить целевое полное давление (раздел 0 методички — самая
   частая и дорогая ошибка в этой предметной области).
2. Построить параболу сети `P = P0·(Q/Q0)²` через скорректированную целевую точку.
3. Для каждой из ≈30 кривых n=const найти пересечение с параболой сети (аналитически).
4. Кандидат проходит фильтр, если пересечение попадает в допустимое окно давления
   `[P_цель·(1-вниз%), P_цель·(1+вверх%)]` и Q пересечения лежит в рабочем диапазоне этой
   кривой (`qRange`).
5. Список кандидатов сортируется по КПД (по убыванию), как в образце принтаута партнёра.
6. Мощность на валу считается через КПД в точке пересечения (`η·P·Q / 3 600 000`), мощность
   двигателя — берётся из таблицы характеристик (ближайший стандартный номинал с запасом).

### Результат

- Список подобранных комплектаций (типоразмер, диаметр, обороты, двигатель), кликабельный.
- При выборе варианта: картинка графика этого типоразмера/диаметра с наложенными (через
  калибровочную матрицу) красной точкой факт. рабочей точки и пунктирной параболой сети — как в
  полной методике оформления результата.
- Текстовая сводка: заданные параметры / факт. параметры (Q, P, КПД, обороты, мощность на валу,
  мощность двигателя) — по образцу принтаута партнёра.
- Вторая секция — чертёж выбранной модели: картинка чертежа этого типоразмера + отфильтрованная
  строка габаритных размеров (не вся сводная таблица) под конкретную модель.

### Обработка ошибок

- Ни одна кривая не прошла фильтр → честное сообщение: «в демо-диапазоне (ВЦ 4-70, №2,5/3,15/4)
  подходящего варианта нет — напишите нам для полного расчёта». Без цифр «80%» и обещаний «за
  минуты» — по духу PRD.
- «Статический» расчёт выбран, но для конкретного графика ось Pdv не удалось откалибровать
  (не должно случиться — она есть на всех вошедших в объём графиках, но если при трассировке
  что-то не получится) → отключить статический вариант для этого типоразмера и явно сказать
  почему.
- Кривая КПД/мощности не читается на графике для конкретной точки → не оценивать «на глаз»,
  помечать «не подтверждено графиком» рядом с полем.

## Проверка перед показом первым пользователям

Сверить расчёт демо на 2-3 контрольных точках по каждому типоразмеру — либо взяв границы
диапазонов из таблицы характеристик каталога, либо (если будет under рукой) реальный кейс,
который Андрей уже считал вручную/через программу партнёра — совпадает ли результат демо с
ожидаемым, прежде чем давать ссылку первым пользователям.

## Структура файлов

- `StartUp/podbor.html` — страница демо (форма + результат), без внешних ресурсов.
- `StartUp/podbor-data.js` (или встроено в `podbor.html`) — оцифрованные данные кривых и
  калибровочные константы.
- `StartUp/assets/podbor/` — обрезанные картинки графиков (по типоразмеру×диаметру) и чертежей
  из каталога, использованные как подложка для точки/выносок.
- Ссылка на `podbor.html` добавляется в блок «Что дальше» лендинга (`index.html`).
