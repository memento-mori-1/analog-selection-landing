# Оцифровка характеристик вентилятора из PDF каталога

Графики каталога (Тепломаш) нарисованы ВЕКТОРНЫМИ путями, поэтому кривые, сетку и линии eta берём
прямо из PDF (pymupdf), а не по пикселям. Все координаты ниже - в пикселях страницы при 300 dpi
(`lib.render_page`), начало в левом верхнем углу страницы.

Файлы: `lib.py` (математика осей/квадратики), `vector_extract.py` (инструмент),
`spec_<типоразмер>.json` (ручная разметка одного типоразмера), `data_<типоразмер>.json` (результат).

## Шаги для нового типоразмера

1. Скелет `data_X.json` (как `data_2_5.json` до оцифровки): для каждого диаметра `d` кривые
   `rpmActual`, `qRangeThousand`, `pRangeExpected` (из таблицы каталога), `motors`, `coeffs: null`.
2. Разметка: для каждого графика найти координаты и записать в `spec_X.json`
   (образец - `spec_2_5.json`):
   ```
   python vector_extract.py inspect "<pdf>" <page_index_0based> [x0 y0 x1 y1]
   ```
   Печатает bbox жирных кривых, диагонали eta и список линий сетки (`y: xmin-xmax`, `x: ymin-ymax`).
   Подписанные линии сетки выступают за рамку (горизонтальные - левее, вертикальные - ниже).
   Сопоставьте их с подписями на осях по картинке (`lib.render_page` -> PNG) и по логарифмическому
   шагу (~одинаковый px/декаду). Поля графика в spec (ключ - `d` как `{d:g}`: `1`, `0.9`, `1.05`):
   `page`, `frame` (рамка графика, жирные кривые и диагонали берутся внутри неё), `crop` (кроп для PNG),
   `qx` (x подписанных линий по `qValues`), `py` (пары `[y, значение Па]`), `pdvx` (x меток шкалы Pdv по
   `pdvValues`), необязательные `qValues`/`pdvValues` на самом графике (если подписи отличаются от общих в
   корне spec; ВЦ 4-70-4), `eta` (значения КПД подряд слева направо по верхним концам диагоналей; число должно
   совпасть с числом диагоналей). Плюс необязательный `drawing` (`crop` + `whiten` - белые прямоугольники
   в координатах кропа; `null` вместо y1 = до низа).
3. Запуск:
   ```
   python vector_extract.py run "<pdf>" spec_X.json data_X.json --out-json data_X.json --out-dir ../../assets/podbor --prefix X
   ```
   Аргументы: PDF; spec; входной data (читается); `--out-json` куда писать результат;
   `--out-dir` куда класть PNG; `--prefix` (напр. `2.5` -> `2.5-D0.9.png`, `2.5-D1.png`, `2.5-drawing.png`).
   Инструмент идемпотентен (можно перезапускать на своём же выводе). Для проверки воспроизводимости
   пишите в другой каталог и сравнивайте с закоммиченным.
4. Проверка против таблицы каталога - `scripts/test-data-2-5.js` (образец для других типоразмеров;
   `test-data-3-15.js` - его копия). Второй пример разметки - `spec_3_15.json` (диагонали eta там слиты в один
   путь с линиями сетки, поэтому `collect` проверяет попадание в `frame` по отрезкам, а не по bbox пути;
   `inspect` печатает диагонали любой толщины < 1.0).

## Что делает `run`

- Жирные кривые (stroke > 1.0): нижняя на картинке = меньшие обороты; сопоставляются с кривыми скелета по
  возрастанию `rpmActual`. Число кривых на графике любое (2 у 2,5 и 3,15; 3 у 4). Если
  несколько кривых слиты в один путь PDF (ВЦ 4-70-4, стр. 1), путь режется на связные цепочки (`path_chains`).
  Короче `MIN_DIAG_PX` отрезки не считаются диагоналями eta (контуры букв). Тонкие чёрные диагонали = линии постоянного КПД (прямые наклона 2 в log-log);
  синие дуги Ny пропускаются.
- Калибровка лог-осей `lib.fit_log_axis` по подписанным линиям: Q по всем `qValues`, Pv только по линиям в
  рабочем диапазоне (значения из [Pmin/1.8, Pmax*1.8] по `pRangeExpected`). Pdv = C*Q^2, C - среднее
  геометрическое по меткам шкалы Pdv.
- 9 точек по длине жирной кривой -> `lib.fit_quadratic` -> `coeffs`.
- `etaSamples`: пересечения кривой с диагоналями (`{q, eta}`); `powerSamples`: мощность на валу в тех же
  точках `kw = Q*1000*P/(3.6e6*eta)` (дуги Ny кривые оборотов не пересекают). Установочная мощность Ny =
  kw * K (запас, ~1.5 для малых мощностей, ~1.3 для 0.55-0.75 кВт).

## Необязательное переопределение coeffC (`pdvCoeffOverride`)

Pdv = rho*v^2/2 зависит только от Q и площади выхода, поэтому `coeffC` одинакова у всех диаметров типоразмера
(2,5: 48.6-49.4; 3,15: 19.4-19.9). Если шкала Pdv на некоторых графиках напечатана со сдвигом относительно шкалы Q
(ВЦ 4-70-4: D=1.05 и 1.1, C~9.0 вместо ~7.6), в корне spec можно задать
`"pdvCoeffOverride": {"graphs": ["1.05", "1.1"], "from": ["0.9", "0.95", "1"], "note": "..."}`. Для графиков из `graphs`
`coeffC` = среднее измеренных C графиков из `from` (2 знака), измеренное значение остаётся в `pdvAxis.coeffCMeasured`,
`pdvAxis.note` = `note`. Без этого ключа поведение прежнее.

## Выходной формат и соглашения

- **Калибровка в пикселях СОХРАНЁННОГО PNG.** `calibration.qAxis` / `pAxis` - `{slope, intercept}` так, что
  `x_px = qAxis.slope * log10(Q_thousand) + qAxis.intercept`, `y_px = pAxis.slope * log10(P_Pa) + pAxis.intercept`,
  где x, y - координаты внутри обрезанного PNG (начало = левый верхний угол PNG, y вниз; `slope` оси P
  отрицательный). Уже вычтено начало кропа (`cropBoxOnPage300dpi`), `imageWidth`/`imageHeight` = размер PNG.
  P - ПОЛНОЕ давление Pv. `pdvAxis.coeffC`: `Pdv = coeffC * Q_thousand^2` (Q в тыс. м3/ч).
- `coeffs` `{a,b,c}`: `P = a*Q^2 + b*Q + c` (Q в тыс. м3/ч, P в Па).
- **`qRangeGraph` / `pRangeGraph`** - фактический участок нарисованной жирной кривой (Q тыс. м3/ч и P Па в
  его концах). Таблица каталога округляет `qRangeThousand`; квадратичную аппроксимацию нельзя
  экстраполировать за `qRangeGraph`. Рабочий диапазон в расчёте (`workingRange` в `podbor-calc.js`) = только `qRangeGraph`; `qRangeThousand` из таблицы используется как запасной вариант, если `qRangeGraph` нет.
- Остатки калибровки `maxResidualPx` обычно 1-3 px; фактический максимум ~6 px (типоразмер 4, D=0,9/0,95; у D=1,0 ось P ~3,2 px). Заметно больше - проверьте сопоставление подписей.
- Исходные PDF каталога в git не лежат (`.gitignore`: `docs/каталог/*.pdf`) - кладите их в `docs/каталог/` вручную.

## Поле КПД и расчётные дуги мощности (`eta_field.py`)

Линии постоянного КПД на графиках — прямые P = a·Q² (Q в тыс. м³/ч), поэтому КПД в любой точке поля
определяется величиной a = P/Q². `python eta_field.py` берёт из PDF положения линий (a) и сопоставляет им значения
КПД из `spec_X.json` (`graphs[d].eta`), результат — `eta_field.json` (его подмешивает `scripts/build-podbor-data.js`
как `etaField` каждого диаметра). По полю строится дуга постоянной мощности на валу N (кВт): Q = (3600·η·N/a)^(1/3),
P = a·Q². Метод проверен по нарисованным синим дугам Nу: расчётные дуги 0,25 и 0,75 кВт (ВЦ 4-70-4 D=0,95) ложатся
на нарисованные, а вдоль каждой нарисованной дуги коэффициент запаса K' = N_ном/N_вал постоянен с разбросом ±3 %.

Измеренные K' по номиналу двигателя (`NOMINAL_K` в `podbor-calc.js`): 0,18 → 1,50; 0,25 → 1,36–1,49; 0,37 → 1,36–1,49;
0,55 → 1,29; 0,75 → 1,30; 1,1 и 1,5 → 1,21; 2,2 → 1,15; 5,5 и 7,5 → 1,10 (только графики ВЦ 4-70-3,15 и 4-70-4 с чистой
разметкой; у ВЦ 4-70-2,5 подписи дуг сопоставить не удалось). Оценка с погрешностью около ±5 %.

**Порядок значений КПД в `spec_X.json`:** «слева направо по верхним концам диагоналей» неоднозначен, когда верхние концы двух
крайних линий стоят почти рядом (ВЦ 4-70-4, D=1,1: были перепутаны 0,66 и 0,73). Проверка: после сортировки по a значения КПД
должны образовать колокол (растут к середине, потом падают).

## Порядок пересборки данных после изменений

1. `python vector_extract.py run ...` — кривые/КПД (`data_X.json`, картинки в `assets/podbor/`), если менялась разметка `spec_X.json`.
2. `python eta_field.py` — поле КПД для расчётных дуг (`eta_field.json`).
3. `node scripts/build-podbor-data.js` — `podbor-data.js` (кривые, поле КПД, рамка поля графика `calibration.plotFrame`).
4. `python scripts/build-podbor-pdf-assets.py` — `podbor-pdf-assets.js` (шрифт Roboto и картинки для PDF; нужны `pip install fonttools font-roboto`).
   Лицензия шрифта — `assets/podbor/fonts/LICENSE-Roboto.txt` (Apache 2.0).

PDF результата подбора формируется в браузере (`podbor-pdf.js`), без внешних библиотек и без окна печати; файл
`podbor-pdf-assets.js` (около 4 МБ) подгружается только по нажатию «Скачать PDF».
