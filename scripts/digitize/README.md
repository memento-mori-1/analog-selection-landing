# Оцифровка характеристик вентилятора из PDF каталога

Графики каталога (Тепломаш) нарисованы ВЕКТОРНЫМИ путями, поэтому кривые, сетку и линии eta берём
прямо из PDF (pymupdf), а не по пикселям. Все координаты ниже - в пикселях страницы при 300 dpi
(`lib.render_page`), начало в левом верхнем углу страницы.

Файлы: `lib.py` (математика осей/квадратики), `vector_extract.py` (инструмент),
`spec_<типоразмер>.json` (ручная разметка одного типоразмера), `data_<типоразмер>.json` (результат).

## Шаги для нового типоразмера

1. Скелет `data_X.json` (как `data_2_5.json` до оцифровки): для каждого диаметра `d` кривые
   `rpmActual`, `qRangeThousand`, `pRangeExpected` (из таблицы каталога), `motors`, `coeffs: null`.
2. Разметка: для каждого графика найти координаты и записать в `spec_X.json`
   (образец - `spec_2_5.json`):
   ```
   python vector_extract.py inspect "<pdf>" <page_index_0based> [x0 y0 x1 y1]
   ```
   Печатает bbox жирных кривых, диагонали eta и список линий сетки (`y: xmin-xmax`, `x: ymin-ymax`).
   Подписанные линии сетки выступают за рамку (горизонтальные - левее, вертикальные - ниже).
   Сопоставьте их с подписями на осях по картинке (`lib.render_page` -> PNG) и по логарифмическому
   шагу (~одинаковый px/декаду). Поля графика в spec (ключ - `d` как `{d:g}`: `1`, `0.9`, `1.05`):
   `page`, `frame` (рамка графика, жирные кривые и диагонали берутся внутри неё), `crop` (кроп для PNG),
   `qx` (x подписанных линий по `qValues`), `py` (пары `[y, значение Па]`), `pdvx` (x меток шкалы Pdv по
   `pdvValues`), `eta` (значения КПД подряд слева направо по верхним концам диагоналей; число должно
   совпасть с числом диагоналей). Плюс необязательный `drawing` (`crop` + `whiten` - белые прямоугольники
   в координатах кропа; `null` вместо y1 = до низа).
3. Запуск:
   ```
   python vector_extract.py run "<pdf>" spec_X.json data_X.json --out-json data_X.json --out-dir ../../assets/podbor --prefix X
   ```
   Аргументы: PDF; spec; входной data (читается); `--out-json` куда писать результат;
   `--out-dir` куда класть PNG; `--prefix` (напр. `2.5` -> `2.5-D0.9.png`, `2.5-D1.png`, `2.5-drawing.png`).
   Инструмент идемпотентен (можно перезапускать на своём же выводе). Для проверки воспроизводимости
   пишите в другой каталог и сравнивайте с закоммиченным.
4. Проверка против таблицы каталога - `scripts/test-data-2-5.js` (образец для других типоразмеров;
   `test-data-3-15.js` - его копия). Второй пример разметки - `spec_3_15.json` (диагонали eta там слиты в один
   путь с линиями сетки, поэтому `collect` проверяет попадание в `frame` по отрезкам, а не по bbox пути;
   `inspect` печатает диагонали любой толщины < 1.0).

## Что делает `run`

- Жирные кривые (stroke > 1.0): нижняя на картинке = меньшие обороты; сопоставляются с кривыми скелета по
  возрастанию `rpmActual`. Тонкие чёрные диагонали = линии постоянного КПД (прямые наклона 2 в log-log);
  синие дуги Ny пропускаются.
- Калибровка лог-осей `lib.fit_log_axis` по подписанным линиям: Q по всем `qValues`, Pv только по линиям в
  рабочем диапазоне (значения из [Pmin/1.8, Pmax*1.8] по `pRangeExpected`). Pdv = C*Q^2, C - среднее
  геометрическое по меткам шкалы Pdv.
- 9 точек по длине жирной кривой -> `lib.fit_quadratic` -> `coeffs`.
- `etaSamples`: пересечения кривой с диагоналями (`{q, eta}`); `powerSamples`: мощность на валу в тех же
  точках `kw = Q*1000*P/(3.6e6*eta)` (дуги Ny кривые оборотов не пересекают). Установочная мощность Ny =
  kw * K (запас, ~1.5 для малых мощностей, ~1.3 для 0.55-0.75 кВт).

## Выходной формат и соглашения

- **Калибровка в пикселях СОХРАНЁННОГО PNG.** `calibration.qAxis` / `pAxis` - `{slope, intercept}` так, что
  `x_px = qAxis.slope * log10(Q_thousand) + qAxis.intercept`, `y_px = pAxis.slope * log10(P_Pa) + pAxis.intercept`,
  где x, y - координаты внутри обрезанного PNG (начало = левый верхний угол PNG, y вниз; `slope` оси P
  отрицательный). Уже вычтено начало кропа (`cropBoxOnPage300dpi`), `imageWidth`/`imageHeight` = размер PNG.
  P - ПОЛНОЕ давление Pv. `pdvAxis.coeffC`: `Pdv = coeffC * Q_thousand^2` (Q в тыс. м3/ч).
- `coeffs` `{a,b,c}`: `P = a*Q^2 + b*Q + c` (Q в тыс. м3/ч, P в Па).
- **`qRangeGraph` / `pRangeGraph`** - фактический участок нарисованной жирной кривой (Q тыс. м3/ч и P Па в
  его концах). Таблица каталога округляет `qRangeThousand`; квадратичную аппроксимацию нельзя
  экстраполировать за `qRangeGraph`. Рабочий диапазон = `qRangeThousand` пересечь `qRangeGraph`.
- Остатки калибровки `maxResidualPx` должны быть порядка 1-2 px; иначе проверьте сопоставление подписей.
